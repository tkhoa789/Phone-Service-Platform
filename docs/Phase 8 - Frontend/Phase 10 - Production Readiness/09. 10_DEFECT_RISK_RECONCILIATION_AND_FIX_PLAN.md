# 10.09 DEFECT & RISK RECONCILIATION AND FIX PLAN

## 1. Executive Summary
This document outlines the bounded Fix Plan for the two P1 Production Blockers discovered during the Phase 10 Production Readiness Audit:
- **SEC-10-002**: Hardcoded Localhost CORS Configuration.
- **PERF-10-001**: Unbounded Database Queries & Client-Side Pagination.

This is a **Reconciliation Plan only**. No code changes have been executed. It awaits Architectural Authorization to commence Fix Wave 1.

---

## 2. FIX PLAN A: SEC-10-002 (Production CORS)

### 2.1 Root Cause
In `Program.cs`, the `StrictCorsPolicy` explicitly hardcodes `"http://localhost:3000"`, `"http://127.0.0.1:3000"`, etc., in the `.WithOrigins(...)` method. This prevents any production frontend hosted on a real domain from communicating with the API.

### 2.2 Affected Components
- `src/backend/PSP.API/Program.cs`
- `src/backend/PSP.API/appsettings.json` (Needs new config section)

### 2.3 Proposed Change
1. Add `"AllowedCorsOrigins": ["http://localhost:3000"]` to `appsettings.json`.
2. Modify `Program.cs` to read `builder.Configuration.GetSection("AllowedCorsOrigins").Get<string[]>()`.
3. If no config is found, fall back to localhost for development safety.

### 2.4 Regression Scope & Acceptance Criteria
- **Scope:** API Transport boundary only.
- **Acceptance:**
  - Localhost development React app can still connect (PASS).
  - Deploying the API with `AllowedCorsOrigins=https://pos.company.com` permits traffic from that domain (PASS).
  - Traffic from `https://malicious-site.com` is rejected by the browser due to CORS (BLOCKED).
  - JWT Authorization remains perfectly intact.

## 3. FIX PLAN B: PERF-10-001 (Unbounded Pagination)

### 3.1 Root Cause
Backend queries (e.g., `GetAllProductsQuery`, `GetAllCustomersQuery`) fetch entire SQL tables into ASP.NET Core RAM (`GetAllAsNoTrackingAsync`), perform in-memory joins, and return massive arrays. The frontend fetches this entire payload and slices it using `(currentPage - 1) * pageSize`. This causes O(N) memory scaling and guarantees OOM crashes under production loads.

### 3.2 Affected Endpoints & Screens
- **Backend:** `ProductQueryHandlers.cs`, `CustomerQueryHandlers.cs`, `RepairQueryHandlers.cs`, `SalesOrderQueryHandlers.cs`, `WarrantyQueryHandlers.cs`, `UserQueryHandlers.cs`, `WarehouseQueryHandlers.cs`, `BranchQueryHandlers.cs`.
- **Frontend Hooks:** `useProducts.ts`, `useCustomers.ts`, etc.
- **Frontend Pages:** All major List Pages (`ProductListPage.tsx`, `CustomerListPage.tsx`, etc.).

### 3.3 Proposed Server-Side Pagination Architecture
**Step 1: Backend DTOs**
Create a universal `PagedResult<T>` in `PSP.Application.Common.Models`:
```csharp
public class PagedResult<T> {
    public IEnumerable<T> Items { get; set; } = new List<T>();
    public int TotalCount { get; set; }
    public int Page { get; set; }
    public int PageSize { get; set; }
}
```

**Step 2: Backend Query Handlers**
Refactor `GetAll[Entity]Query` to `Get[Entity]PagedQuery`:
- Leverage `_unitOfWork.Repository<T>().GetQueryableAsNoTracking()`.
- Apply `Where(filters)`.
- Extract `TotalCount = await query.CountAsync()`.
- Apply `.Skip((request.Page - 1) * request.PageSize).Take(request.PageSize)`.
- Project to DTOs.
- Return `PagedResult<Dto>`.

**Step 3: Frontend API Hooks**
Update frontend `api.ts` and `hooks.ts` to expect `PagedResult<T>` instead of `T[]`. Remove client-side `.slice()` logic from all `ListPage.tsx` components. Utilize the returned `totalCount` for the Pagination component.

### 3.4 API Contract Impact
- **Breaking Change:** Yes. Frontend must be updated synchronously with Backend. The response changes from `ApiResponse<T[]>` to `ApiResponse<PagedResult<T>>`.

### 3.5 Regression Scope & Acceptance Criteria
- **Scope:** All List views across the application.
- **Acceptance:**
  - `pageSize = 20` must return exactly 20 (or fewer) records in the network payload.
  - SQL Server Profiler/Logs must show `OFFSET X ROWS FETCH NEXT Y ROWS ONLY`.
  - Frontend pagination controls (Next/Prev) continue to function.
  - Search/Filter operations still yield correct filtered results on Page 1.
  - CRUD operations (Add/Edit) continue to refresh the list correctly without breaking the Phase 09 Acceptance tests.
