# 08.16 DESIGN SYSTEM MIGRATION PLAN

## Strategy
Migration to the Design System will be **GRADUAL**. Do not blindly rewrite 100% of the codebase using regex. Primitives will be introduced, and critical screens will be migrated first. Legacy screens will continue to function until their migration is justified by feature updates.

## Prioritization Matrix

### P0 — Immediate Action (Must Fix)
*Screens/Components with broken UX or accessibility that actively hinder usage.*
- MainLayout and Sidebar: Fix hardcoded margins (ml-64) breaking mobile responsiveness.
- PosPage.tsx: Fix unreadable corrupted text encoding for Vietnamese strings.

### P1 — High-Value Core Screens
*Screens where consistency and UX have high business impact.*
- **Sales / POS**: High interaction density. Buttons, inputs, and modals must be standardized.
- **Repairs**: Complex intake forms and tables. Needs standard FormField, Badge, and Table implementations.

### P2 — Frequently Modified Screens
*Screens that should be migrated to establish good patterns for future edits.*
- **Inventory & Stock Take**: Standardize cards and inputs.
- **Warranty**: Standardize swap modals (ConfirmDialog).

### P3 — Legacy / Low-Risk Screens
*Screens that function acceptably and have low ROI for immediate migration.*
- **Auth (Login)**: Works fine.
- **Dashboard**: Works fine.
- **AuditLog**: Internal tool, works fine.

### P4 — Do Not Touch
- Any screen not explicitly requiring migration unless actively being modified for a new feature.
