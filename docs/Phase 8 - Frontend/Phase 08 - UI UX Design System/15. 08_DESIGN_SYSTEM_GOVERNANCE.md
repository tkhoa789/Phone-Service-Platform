# 08.15 DESIGN SYSTEM GOVERNANCE

## Core Philosophy
The frontend UI is built upon a standard Design System. To prevent UI fragmentation (e.g., 89 different button styles), all future UI development must adhere to these engineering governance rules.

## Governance Rules

- **UI-001 (Primitives First)**: Do not write raw Tailwind classes for interactive elements if a standard primitive component exists. *Exception: Allowed with architectural justification for unique one-off promotional screens.*
- **UI-002 (Token Discipline)**: Do not introduce new colors, shadows, or spacing values outside of the established CSS variables without explicit justification.
- **UI-003 (Semantic Modals)**: All overlays, modals, and dialogs must utilize the Dialog primitive to ensure proper ole, ria-modal, and focus trapping.
- **UI-004 (Form Integrity)**: Form fields must encapsulate their label, input control, and validation error state using the FormField pattern.
- **UI-005 (Loading Consistency)**: Loading states must use the standardized Spinner or Skeleton pattern rather than raw text.
- **UI-006 (Destructive Safety)**: Any destructive action must use the standardized ConfirmDialog pattern before execution.
- **UI-007 (No Ad-Hoc Abstractions)**: Do not create highly specific wrapper components (e.g., SuperCard) for a single screen. Use composition.
- **UI-008 (Responsive Boundaries)**: Do not hardcode custom breakpoints. Stick to standard Tailwind breakpoints (sm, md, lg, xl) and ensure mobile-first behavior.
- **UI-009 (Separation of Concerns)**: UI Primitives in src/components/ui/ must remain strictly presentation-oriented. No API calls or business logic allowed inside them.
