# 08.18 DESIGN TOKEN SPECIFICATION

## Current Assessment
The application uses a Neumorphism style relying on a Light/Dark theme map in index.css. 

## Defined Tokens (CSS Variables)

### Colors (Surface & Background)
- --neu-bg-base: Primary background color (Light/Dark aware).
- --neu-border: Standard border color.

### Text
- --neu-text-title: Headings and primary emphasis.
- --neu-text-sub: Body text and secondary emphasis.

### Brand & Accents
- --neu-accent-mint: Primary brand color.
- --neu-accent-mint-glow: Neon glow effect for active states.

### Shadows (Neumorphic)
- --neu-shadow-outer: Default convex surface.
- --neu-shadow-hover: Lifted convex surface.
- --neu-shadow-inset: Pressed/active concave surface.
- --neu-shadow-button: Convex surface specific to interactive controls.

## Missing / Inconsistent Tokens
The following logical tokens should be established via Tailwind @apply or directly in components to replace hardcoded values like 	ext-rose-500 or g-amber-100:
- **Intent Colors**: Success, Warning, Danger, Info.
- **Typography**: Explicit utility classes for heading-1, ody-sm, etc., though existing Tailwind text sizing is mostly acceptable.

## Governance
No new CSS variables should be added to index.css unless an entirely new semantic concept is introduced.
